# Документация Game of Life

Документ описывает программу
[`src/game_of_life_without_typedef.c`](src/game_of_life_without_typedef.c):
формат входных данных, алгоритм симуляции, назначение всех функций и
используемые возможности библиотеки `ncurses`.

## 1. Назначение программы

Программа визуализирует клеточный автомат Джона Конвея «Игра Жизнь» в
терминале.

Основные возможности:

- поле из 80 столбцов и 25 строк;
- замкнутые границы: противоположные стороны поля считаются соседними;
- загрузка начального состояния через стандартный поток ввода;
- цветное отображение живых клеток, если терминал поддерживает цвета;
- изменение скорости клавишами `A` и `Z`;
- завершение по клавише `Space`;
- ASCII-рамка вокруг поля.

С учётом рамки для полного отображения требуется терминал размером не менее
82 столбцов и 27 строк.

## 2. Сборка и запуск

Пример сборки:

```sh
cc -std=c11 -Wall -Wextra -Werror -pedantic \
  src/game_of_life_without_typedef.c -lncurses -o game_of_life
```

Пример запуска с готовой конфигурацией:

```sh
./game_of_life < src/patterns/blinker.txt
```

Начальная матрица читается из `stdin`. После её загрузки программа открывает
`/dev/tty`, чтобы получать интерактивные нажатия клавиш из терминала, даже
если `stdin` был перенаправлен из файла.

## 3. Представление данных

### 3.1. Игровое поле

Поле объявляется как обычный двумерный массив:

```c
int field[HEIGHT][WIDTH] = {0};
```

Состояния клеток:

- `0` — мёртвая клетка;
- `1` — живая клетка.

Индексы массива:

- `field[row][column]`;
- `row` находится в диапазоне от `0` до `HEIGHT - 1`;
- `column` находится в диапазоне от `0` до `WIDTH - 1`.

Ключевое слово `const` у параметров вида
`const int field[HEIGHT][WIDTH]` запрещает функции изменять переданное поле.
Сам массив при вызове функции не копируется: параметр преобразуется в
указатель на его строки.

### 3.2. Структура `Terminal`

```c
struct Terminal {
    SCREEN *screen;
    FILE *input;
};
```

Поля структуры:

- `screen` хранит контекст экрана, созданный функцией `newterm()`;
- `input` хранит открытый поток `/dev/tty`, из которого `ncurses` получает
  интерактивный ввод.

При создании структура обнуляется:

```c
struct Terminal terminal = {NULL, NULL};
```

## 4. Константы программы

| Константа | Значение | Назначение |
|---|---:|---|
| `WIDTH` | `80` | Количество столбцов игрового поля |
| `HEIGHT` | `25` | Количество строк игрового поля |
| `LIVE_CELL` | `'*'` | Символ живой клетки |
| `DEAD_CELL` | `' '` | Символ мёртвой клетки |
| `HORIZONTAL_BORDER` | `'-'` | Горизонтальная часть рамки |
| `VERTICAL_BORDER` | `'|'` | Вертикальная часть рамки |
| `BORDER_CORNER` | `'+'` | Углы рамки |
| `START_DELAY` | `200` | Начальная задержка между поколениями, мс |
| `DELAY_STEP` | `25` | Шаг изменения задержки, мс |
| `MIN_DELAY` | `25` | Минимальная задержка |
| `MAX_DELAY` | `1000` | Максимальная задержка |
| `LIVE_COLOR_PAIR` | `1` | Номер цветовой пары живой клетки |
| `DEAD_COLOR_PAIR` | `2` | Номер цветовой пары мёртвой клетки |

## 5. Формат входных данных

Программа принимает ровно 25 строк, каждая из которых должна содержать ровно
80 распознанных клеток.

Допустимые символы живой клетки:

```text
1 * #
```

Допустимые символы мёртвой клетки:

```text
0 .
```

Игнорируемые разделители:

- пробел;
- табуляция `\t`;
- возврат каретки `\r`, используемый в окончаниях строк `\r\n`.

Символ перевода строки `\n` завершает текущую строку поля. Последняя строка
может завершаться концом файла без `\n`.

Ввод считается некорректным, если:

- строк меньше или больше 25;
- в строке не ровно 80 клеток;
- встретился неизвестный символ;
- встретилась пустая строка;
- после полной матрицы присутствует дополнительная строка.

При ошибке программа выводит:

```text
n/a
```

и возвращает код завершения `1`.

## 6. Правила Game of Life

Для каждой клетки подсчитываются восемь соседей:

```text
↖  ↑  ↗
←  X  →
↙  ↓  ↘
```

Следующее состояние определяется так:

- мёртвая клетка оживает, если у неё ровно три живых соседа;
- живая клетка выживает, если у неё два или три живых соседа;
- во всех остальных случаях клетка становится или остаётся мёртвой.

Поле замкнуто само на себя. Например:

- сосед сверху от строки `0` находится в строке `HEIGHT - 1`;
- сосед слева от столбца `0` находится в столбце `WIDTH - 1`;
- сосед снизу от последней строки находится в строке `0`.

Новое поколение записывается в отдельный массив `next`. Это необходимо,
чтобы все клетки рассчитывались по одному и тому же старому состоянию. После
полного расчёта `next` копируется в `field`.

## 7. Общий поток выполнения

```text
main
  ├─ чтение и проверка начального поля
  └─ run_game
       ├─ открытие /dev/tty и создание экрана ncurses
       ├─ настройка терминала и цветов
       ├─ отрисовка поля
       ├─ обработка клавиш
       ├─ расчёт следующего поколения
       ├─ копирование нового поля
       ├─ задержка
       └─ восстановление терминала и освобождение ресурсов
```

Основной цикл продолжается до нажатия `Space`.

## 8. Функции программы

### 8.1. `main`

```c
int main(void);
```

Точка входа программы.

1. Создаёт и обнуляет массив `field`.
2. Вызывает `read_field()`.
3. При ошибке печатает `n/a` и возвращает `1`.
4. При успешном чтении вызывает `run_game()`.
5. Возвращает итоговый код завершения.

### 8.2. Функции чтения поля

#### `read_field`

```c
int read_field(int field[HEIGHT][WIDTH]);
```

Читает начальную матрицу из `stdin` по одному символу с помощью `getchar()`.

- `\n` передаётся в `finish_input_row()`;
- игнорируемые разделители пропускаются;
- остальные символы передаются в `store_cell()`;
- при конце файла завершает последнюю строку, если в ней есть клетки.

Возвращает `1`, только если получено ровно `HEIGHT` корректных строк. При
любой ошибке возвращает `0`.

#### `store_cell`

```c
int store_cell(int field[HEIGHT][WIDTH], int *row, int *column,
               int symbol);
```

Проверяет координаты и записывает одну клетку:

- живой символ преобразуется в `1`;
- мёртвый символ преобразуется в `0`;
- после успешной записи увеличивается `*column`;
- неизвестный символ или выход за размеры поля приводит к ошибке.

Возвращает `1` при успешной записи и `0` при ошибке.

#### `finish_input_row`

```c
int finish_input_row(int *row, int *column);
```

Завершает чтение текущей строки матрицы. Строка считается корректной, если:

- номер строки меньше `HEIGHT`;
- было прочитано ровно `WIDTH` клеток.

При успехе увеличивает `*row`, обнуляет `*column` и возвращает `1`. Иначе
возвращает `0` и не изменяет координаты.

#### `is_live_symbol`

```c
int is_live_symbol(int symbol);
```

Возвращает истинное значение для символов `'1'`, `'*'` и `'#'`.

#### `is_dead_symbol`

```c
int is_dead_symbol(int symbol);
```

Возвращает истинное значение для символов `'0'` и `'.'`.

#### `is_ignored_symbol`

```c
int is_ignored_symbol(int symbol);
```

Возвращает истинное значение для пробела, табуляции и `\r`. Эти символы не
считаются клетками и не увеличивают номер столбца.

### 8.3. Функции игровой логики

#### `wrap_coordinate`

```c
int wrap_coordinate(int coordinate, int limit);
```

Замыкает одну координату:

- отрицательная координата заменяется на `limit - 1`;
- координата, равная или превышающая `limit`, заменяется на `0`;
- остальные координаты возвращаются без изменения.

В программе функция получает координаты, отклоняющиеся от допустимого
диапазона максимум на единицу.

#### `count_neighbors`

```c
int count_neighbors(const int field[HEIGHT][WIDTH], int row, int column);
```

Подсчитывает живых соседей клетки `(row, column)`.

Два вложенных цикла перебирают смещения строк и столбцов от `-1` до `1`.
Смещение `(0, 0)` пропускается, поскольку соответствует самой клетке. Для
каждого из оставшихся восьми смещений координаты замыкаются функцией
`wrap_coordinate()`, после чего значение `0` или `1` прибавляется к счётчику.

Возвращаемое значение находится в диапазоне от `0` до `8`.

#### `next_cell_state`

```c
int next_cell_state(int current_state, int neighbors);
```

Применяет правила Game of Life к одной клетке. Возвращает `1`, если:

- соседей ровно три; или
- клетка сейчас живая и соседей ровно два.

Во всех остальных случаях возвращает `0`.

#### `calculate_generation`

```c
void calculate_generation(const int current[HEIGHT][WIDTH],
                          int next[HEIGHT][WIDTH]);
```

Обходит все клетки поля. Для каждой клетки вызывает `count_neighbors()` и
`next_cell_state()`, затем записывает результат в соответствующую клетку
массива `next`.

`current` объявлен как `const`, поэтому функция не может случайно изменить
исходное поколение во время расчёта.

#### `copy_field`

```c
void copy_field(const int source[HEIGHT][WIDTH],
                int destination[HEIGHT][WIDTH]);
```

Копирует каждую клетку из `source` в `destination`. В основном цикле переносит
готовое поколение из `next` в `field`.

### 8.4. Функции терминала и игрового цикла

#### `open_terminal`

```c
int open_terminal(struct Terminal *terminal);
```

Подготавливает отдельный поток для интерактивного ввода:

1. Открывает `/dev/tty` функцией `fopen()`.
2. Создаёт контекст `ncurses` функцией `newterm()`.
3. Делает созданный контекст текущим с помощью `set_term()`.

Возвращает `1` при полном успехе и `0` при ошибке.

Использование `/dev/tty` отделяет клавиатурный ввод игры от `stdin`, из
которого ранее была прочитана начальная матрица.

#### `close_terminal`

```c
void close_terminal(struct Terminal *terminal);
```

Завершает работу с терминалом:

1. `endwin()` восстанавливает обычный режим терминала.
2. `delscreen()` освобождает контекст `SCREEN`.
3. `fclose()` закрывает `/dev/tty`.

#### `configure_terminal`

```c
int configure_terminal(void);
```

Настраивает интерактивный режим:

- отключает вывод нажатых клавиш;
- включает посимвольный ввод без ожидания Enter;
- скрывает курсор;
- включает неблокирующее чтение клавиш;
- включает обработку специальных клавиш;
- при поддержке цветов вызывает `initialize_colors()`.

Возвращает `1`, если цветной режим успешно настроен, иначе `0`. Ошибка цветов
не останавливает игру: она продолжает работать в монохромном режиме.

#### `initialize_colors`

```c
int initialize_colors(void);
```

Инициализирует цветовую подсистему `ncurses` и две цветовые пары:

- зелёный текст на стандартном фоне для живых клеток;
- чёрный текст на стандартном фоне для мёртвых клеток.

Каждый вызов проверяется на `ERR`. Возвращает `1`, только если вся
инициализация завершилась успешно.

#### `draw_field`

```c
void draw_field(const int field[HEIGHT][WIDTH], int colors_enabled);
```

Полностью формирует очередной кадр:

1. Очищает виртуальный экран `ncurses`.
2. Рисует верхнюю и нижнюю части рамки.
3. Рисует боковые части рамки.
4. Обходит все клетки поля.
5. Выбирает символ и цветовые атрибуты клетки.
6. Рисует клетку со смещением `(1, 1)`, чтобы рамка не перекрывала поле.
7. Вызывает `refresh()` для фактического обновления терминала.

Если цветной режим включён, живая клетка рисуется зелёной и жирной.

#### `handle_input`

```c
int handle_input(int *delay);
```

Получает все клавиши, уже находящиеся в очереди ввода. Поскольку установлен
неблокирующий режим, `getch()` возвращает `ERR`, когда очередь пуста.

- `Space` устанавливает признак завершения;
- другие клавиши передаются в `change_speed()`.

Возвращает `1`, если игру следует завершить, иначе `0`.

#### `change_speed`

```c
void change_speed(int key, int *delay);
```

Изменяет задержку между поколениями:

- `A` или `a` уменьшает задержку на `DELAY_STEP`, поэтому игра ускоряется;
- `Z` или `z` увеличивает задержку, поэтому игра замедляется;
- значение ограничивается диапазоном от `MIN_DELAY` до `MAX_DELAY`;
- остальные клавиши игнорируются.

#### `run_game`

```c
void run_game(int field[HEIGHT][WIDTH]);
```

Управляет жизненным циклом игры.

1. Создаёт массив следующего поколения и структуру терминала.
2. Открывает терминал.
3. Настраивает режим ввода и цвета.
4. В цикле рисует поле и обрабатывает клавиши.
5. Если завершение не запрошено, рассчитывает новое поколение.
6. Копирует новое поколение в текущее поле.
7. Приостанавливает выполнение на заданное количество миллисекунд.
8. После выхода из цикла закрывает терминал.

## 9. Используемые функции и объекты `ncurses`

`ncurses` хранит виртуальное изображение экрана в памяти. Функции рисования
сначала изменяют это виртуальное изображение, а `refresh()` синхронизирует его
с реальным терминалом. Благодаря этому программа не обязана вручную печатать
управляющие ANSI-последовательности.

### 9.1. Создание и закрытие экрана

#### `newterm`

```c
SCREEN *newterm(const char *type, FILE *output, FILE *input);
```

Инициализирует новый контекст терминала и возвращает `SCREEN *`. В программе:

```c
newterm(NULL, stdout, terminal->input);
```

- `NULL` означает использование типа терминала из переменной окружения
  `TERM`;
- `stdout` используется для вывода изображения;
- `terminal->input`, связанный с `/dev/tty`, используется для клавиатуры.

При ошибке возвращает `NULL`.

Здесь используется `newterm()`, а не более простая `initscr()`, потому что
программе нужно явно назначить отдельный входной поток для интерактивного
управления.

#### `set_term`

```c
SCREEN *set_term(SCREEN *new_screen);
```

Делает указанный контекст текущим. Последующие вызовы `ncurses` работают с
этим экраном. Возвращает предыдущий текущий контекст.

#### `endwin`

```c
int endwin(void);
```

Завершает полноэкранный режим, восстанавливает настройки терминала и делает
его пригодным для обычного вывода оболочки. Не освобождает сам объект
`SCREEN`.

#### `delscreen`

```c
void delscreen(SCREEN *screen);
```

Освобождает память и внутренние структуры, связанные с контекстом `SCREEN`.
Вызывается после `endwin()`.

### 9.2. Настройка клавиатуры и терминала

#### `noecho`

```c
int noecho(void);
```

Отключает автоматическое отображение вводимых символов. Без этого нажатия
`A`, `Z` и `Space` могли бы появляться поверх игрового поля.

#### `cbreak`

```c
int cbreak(void);
```

Включает посимвольную передачу ввода программе. Клавиши становятся доступны
сразу, без ожидания Enter. Обработка специальных управляющих символов
терминала при этом в основном сохраняется.

#### `curs_set`

```c
int curs_set(int visibility);
```

Изменяет видимость курсора:

- `0` — скрыть;
- `1` — обычный курсор;
- `2` — хорошо заметный курсор, если терминал поддерживает этот режим.

Программа вызывает `curs_set(0)`.

#### `nodelay`

```c
int nodelay(WINDOW *window, bool enabled);
```

Управляет блокировкой чтения для окна. Вызов

```c
nodelay(stdscr, TRUE);
```

делает `getch()` неблокирующим. Если клавиш нет, функция немедленно возвращает
`ERR`, и симуляция может продолжить работу.

#### `keypad`

```c
int keypad(WINDOW *window, bool enabled);
```

Включает распознавание функциональных и специальных клавиш терминала как
единых значений `KEY_*`. Текущая версия использует обычные клавиши, но
включённый режим упрощает дальнейшее добавление стрелок или обработку
`KEY_RESIZE`.

#### `getch`

```c
int getch(void);
```

Читает клавишу из стандартного окна `stdscr`. Возвращаемый тип `int` нужен,
поскольку результатом может быть как обычный символ, так и специальный код
`KEY_*` либо значение `ERR`.

В неблокирующем режиме `ERR` означает, что доступных клавиш сейчас нет.

### 9.3. Отрисовка

#### `erase`

```c
int erase(void);
```

Помечает всё стандартное окно `stdscr` как очищенное. Фактическое обновление
терминала произойдёт при последующем `refresh()`.

#### `mvaddch`

```c
int mvaddch(int row, int column, chtype character);
```

Перемещает виртуальный курсор в координаты `(row, column)` и помещает туда
символ. Координата строки указывается первой.

Тип `chtype` может содержать не только код символа, но и атрибуты. Поэтому в
программе символ объединяется с цветом и жирным начертанием:

```c
mvaddch(row + 1, column + 1, symbol | attributes);
```

Смещение на единицу оставляет место для рамки.

#### `refresh`

```c
int refresh(void);
```

Сравнивает виртуальный экран с текущим состоянием терминала и выводит только
необходимые изменения. Завершает построение одного кадра.

#### `napms`

```c
int napms(int milliseconds);
```

Приостанавливает выполнение как минимум на указанное количество миллисекунд.
Определяет частоту смены поколений.

### 9.4. Цвета и атрибуты

#### `has_colors`

```c
bool has_colors(void);
```

Сообщает, поддерживает ли текущий терминал цвета. Если нет, программа не
пытается создавать цветовые пары.

#### `start_color`

```c
int start_color(void);
```

Активирует цветовую подсистему `ncurses`. Должна быть вызвана до использования
цветовых пар.

#### `use_default_colors`

```c
int use_default_colors(void);
```

Разрешает использовать стандартные цвета терминала. После успешного вызова
значение `-1` в `init_pair()` означает стандартный цвет переднего или заднего
плана. Это расширение `ncurses`, а не базовая возможность всех реализаций
`curses`.

#### `init_pair`

```c
int init_pair(short pair, short foreground, short background);
```

Связывает номер цветовой пары с цветами текста и фона. Программа создаёт:

```c
init_pair(LIVE_COLOR_PAIR, COLOR_GREEN, -1);
init_pair(DEAD_COLOR_PAIR, COLOR_BLACK, -1);
```

`COLOR_GREEN` и `COLOR_BLACK` — стандартные цветовые константы `ncurses`, а
`-1` означает фон терминала.

#### `COLOR_PAIR`

```c
COLOR_PAIR(pair_number)
```

Макрос преобразует номер пары в атрибут, пригодный для объединения с символом
через побитовое `|`.

#### `A_BOLD`

Атрибут жирного или повышенно яркого начертания. Для живой клетки программа
объединяет его с зелёной цветовой парой:

```c
COLOR_PAIR(LIVE_COLOR_PAIR) | A_BOLD
```

### 9.5. Типы, окна и служебные значения

#### `SCREEN`

Непрозрачный тип контекста терминала. Его внутреннее устройство контролирует
библиотека; программа хранит и передаёт только указатель `SCREEN *`.

#### `stdscr`

Указатель на стандартное окно `ncurses`, занимающее доступную область экрана.
Функции `erase()`, `getch()`, `mvaddch()` и `refresh()` без префикса `w`
работают именно с ним.

#### `ERR`

Значение ошибки `ncurses`, обычно равное `-1`. В `handle_input()` оно также
служит признаком пустой очереди при неблокирующем вводе.

#### `TRUE`

Истинное значение, используемое API `ncurses`. Передаётся в `nodelay()` и
`keypad()` для включения соответствующих режимов.

## 10. Используемые средства стандартной библиотеки C

| Средство | Назначение в программе |
|---|---|
| `getchar()` | Читает очередной символ начальной матрицы из `stdin` |
| `printf()` | Выводит `n/a` при ошибке |
| `fopen()` | Открывает `/dev/tty` для интерактивного ввода |
| `fclose()` | Закрывает поток `/dev/tty` |
| `FILE` | Тип стандартного файлового потока |
| `stdout` | Поток, в который `ncurses` выводит изображение |
| `EOF` | Признак конца входного потока |
| `NULL` | Нулевой указатель, используемый при инициализации и проверках |

## 11. Управление

| Клавиша | Действие |
|---|---|
| `A` или `a` | Ускорить игру: уменьшить задержку |
| `Z` или `z` | Замедлить игру: увеличить задержку |
| `Space` | Завершить игру |

Изменяется именно задержка, поэтому меньшее значение `delay` означает более
высокую скорость.

## 12. Особенности текущей реализации

- `/dev/tty` является Unix-путём и не переносим на Windows без изменения
  терминального кода.
- Размер терминала явно не проверяется; для рамки и поля требуется минимум
  82×27 символов.
- При неподдерживаемых цветах игра автоматически работает без цвета.
- Ввод начального состояния выполняется до запуска `ncurses`.
- Если открыть интерактивный терминал не удалось, `run_game()` печатает `n/a`
  и возвращается. В текущей реализации этот случай не меняет код возврата
  `main()` на `1`.
- Функции рисования `ncurses` возвращают `ERR` при невозможности вывода, но
  текущая версия не проверяет эти результаты.
